# 生成した証明は何を検証すればよいか

LLMが書いた証明を採用するときは、**意図した命題・証明の受理・依存する仮定・評価条件**を別々に確かめる。流暢な説明や正解文字列との一致だけでは、この四つは分からない。本稿は検証手順を選ぶための整理である。

## 一次資料で確認したこと

- **Lean公式手引き**：カーネルが受理するのは、定義・公理などを含む環境内の形式命題への証明である。自然言語の問題との対応は別途確認する必要がある。依存先の未完成証明は、現在の定理の表示だけでは見落とし得る。[出典][lean]
- **TRIGO**：三角関数式の簡約を扱い、探索上限内で正しい証明を得た問題の割合を測る。Lean-Gymの「no goals」を成功判定に用いる一方、証明経路の多様性は十分に測れていないと述べる。[§6.2・§9][trigo]
- **TheoremLlama**：自然言語の説明をLeanコードのコメントに組み込み、コメント除去後のコードが元と同じかを検査する。さらに、Leanで検証された生成証明を次の反復の例に使う。[§2.1.3・§2.3][theoremllama]

## このノートの整理：採用までの確認順

1. **命題を固定する。** 対象の型、量化、仮定、結論を元の問題と照合する。証明を簡単にするための仮定追加や、別の定義への置き換えがないかを見る。命題と証明を同時生成する場合は、ここが特に重要になる。
2. **証明全体を確認する。** 固定した命題に対して最後まで検査し、未解決の目標・エラー・警告を記録する。文字列採点は書式診断用に分ける。コメントの保存検査はコード改変を検出できるが、説明内容の論理的な正しさまで保証するわけではない、というのが本稿の読み取りである。
3. **前提を点検する。** `#print axioms 定理名`で間接依存も調べる。`sorryAx`は未完成部分を示す。`propext`等の数学で使う標準公理と、独自公理やネイティブ計算による追加の信頼は区別する。公理が一つでもあれば失格、という基準にはしない。[Lean公理の説明][axioms]
4. **実行環境を守る。** 未レビューの生成コードを日常の作業環境でそのまま動かさない。Leanのタクティク等には任意の処理を実行できるものがある。高リスクな提出物には、信頼できる側で固定した命題と隔離実行・外部チェッカーを組み合わせる手順が公式に示されている。[Lean手引き][lean]
5. **比較条件を残す。** 本稿では、Lean・ライブラリの版、入力命題、生成前後の出力、試行回数、探索・時間上限、成功と失敗のログを保存する運用を勧める。修正後に通った結果を「初回生成の成功」と混ぜず、タイムアウトを反証とも扱わない。

## 小さな例：文字列と命題を混同しない

「自然数に0を足しても変わらない」を、次のように固定する。

```lean
theorem add_zero_demo (n : Nat) : n + 0 = n := by
  exact Nat.add_zero n

#print axioms add_zero_demo
```

これは説明用の例で、ここでは未実行。同じ目標には`rfl`という別の書き方もあるため、模範解答との文字列不一致だけで誤答にしない。一方、生成器が`n = 0`という仮定を追加したなら、確認する命題の範囲が狭くなる。証明の受理と問題設定の保存を両方調べる理由がここにある。

## 使いどころと限界

教材の採点では「命題固定＋証明検査」、研究比較ではさらに「同じ探索予算＋未解決理由の集計」、外部から集める証明では「隔離＋依存関係の監査」を優先する。TRIGOのように分布や難易度を変えた評価も、単一の成功率を一般的な数学能力へ広げすぎないために役立つ。

機械検査が通っても、説明の教育的な良さや元の問題の形式化の適切さは別に評価する。基礎となる論理や検査系への信頼も残る。本稿では既存メモの実験ログを再実行しておらず、過去の成功率を追認したり、現在のモデル順位として扱ったりしていない。

## 既存メモへの読み進め方

1. [Leanベンチマークの研究サマリ](../articles/2025/202510.md#lean-benchmark-summary)：文字列評価と実行評価の問題意識を読む。数値は当時の記録として扱う。
2. [TRIGO](../papers/2023/README.md#trigo)：評価対象・生成分布・探索条件を具体化する。
3. [TheoremLlama](../papers/2024/README.md#theoremllama)：説明付きデータと反復生成を検証工程に結び付ける。
4. [DeepSeek-Prover](../papers/undated.md#deepseek-prover)：合成命題の品質管理へ進む入口。詳細はリンク先の原論文で再確認する。

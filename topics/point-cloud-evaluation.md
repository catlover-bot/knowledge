# 同じ物体を別ファイルにしても、未知の物体は増えない

たとえば、ある椅子のスキャンから点を取り直して、点群A1とA2を作る。A1で学習してA2でよく当たったとき、「初めて見る椅子にも強い」と言ってよいだろうか。

この例ではまだ言えない。点の座標やファイル名が変わっても、元の椅子は同じだからだ。新しいサンプリングへの対応と、未知の物体への汎化を分けるところから評価を組みたい。以下は公開文献をもとにした評価設計のノートで、A1・A2は説明用の架空例。実験結果は含めていない。

## 「未知」をどこに置くか

![同じ椅子A由来のA1とA2を学習とテストに分けた場合と、椅子Aを学習・椅子Bをテストにまとめた場合を比べる図](../assets/diagrams/pointcloud-evaluation-split.svg)

上は別サンプル、下は別物体。どちらもファイル名は重複していないが、答えられる問いが違う。図では検証用データを省略した。実際の設定選択には、テストと別の検証用グループも確保する。

KapoorとNarayananは、重複や前処理だけでなく、学習とテストの間の依存も漏洩の問題として整理している。[2] この椅子の例に当てはめるなら、ファイルをシャッフルする前に元物体のIDが必要になる。ハッシュが違う二つのファイルでも、同じ形状から派生した可能性は残る。

未知物体を測るなら物体ID、未知セッションなら取得セッションID、未知被験者なら被験者IDで分ける。物体とセッションの両方を未知にしたい場合は少し厄介だ。複合キーを作っただけでは、同じ物体が別セッションを通じて両側へ入ることがある。どの依存を切りたいのかを決めてから、IDの重なりを確かめる。

GroupKFoldは渡したグループをfold間で分離してくれる。[4] ただし、そのグループが研究の問いに合っているかは別に考える必要がある。取得元IDを発見したり、将来のデータを過去に混ぜないようにしたりする処理まで任せられるわけではない。

## 点を並べ替える、点を落とす、物体を替える

PointNetの順序不変性は、**同じ点集合の入力順を変える**話だ。[1] 分類結果を比べるなら同じ出力になる性質を見る。点ごとの予測を比べるなら、点の対応を元の順に戻してから確かめる。

点を欠落させれば集合そのものが変わる。座標ノイズ、密度変化、回転も、並べ替えとは条件が違う。ここでは無劣化時の成績と、劣化の種類・強度ごとの低下を残す。さらに物体そのものを替える評価が、冒頭の分割の話につながる。

「頑健だった」と一行で済ませると、この三つが混ざる。どの操作に対する結果かまで書いておきたい。ModelNet-CとModelNet40-Cも同じ指標ではないので、名前、版、集計法は[ベンチマーク比較](../papers/2022/point-cloud-corruptions.md)へ戻って確認する。

## 正規化はどのデータを見たか

分割は拡張の前に決める。全体から推定する正規化統計や特徴選択は、学習側だけでfitし、検証・テストには同じ変換を適用する。交差検証でも、各foldの学習側でやり直す。[3]

一方で、入力点群一つだけから中心を引く固定処理と、データセット全体から統計を求める処理は区別したい。前者であっても、絶対位置や尺度を消してよい課題なのかは残る。実際の利用時に手に入る情報か、予測に必要な情報を捨てていないかを、前処理ごとに記録する。

学習で重みを更新し、検証でハイパーパラメータ、停止時点、チェックポイントを選ぶ。分割、前処理、評価条件、seed一覧を固定してからテストを開く。結果を見て設定を変えたなら、その結果は次の選択に使われている。変更を記録し、独立した最終評価とは区別する。

### テスト時適応を入れる場合

テスト中にモデルや統計を更新する方法もある。[5] そのときは「テストでは何も学習しない」という説明では足りない。

- 正解ラベルを使うのか。教師なし適応なら、ラベルを適応や設定選択に使わない。
- 更新するのはモデルのどこか。更新前と更新後のどちらの出力を採点するか。
- 一つの入力、バッチ、全テスト集合のどこまで見てよいか。
- 入力順序をどう決め、どこで状態をリセットするか。未来の入力を先に見てよいか。

この条件が違えば、同じテスト集合でも別の比較になる。通常の推論と適応ありの結果は、条件を添えて分けて読む。

## 点が多いことと、独立した対象が多いこと

一つの物体から多くの点を取っても、物体を多数集めた評価にはならない。同じ物体に何種類もの劣化を加えた場合も、独立に取得した物体の数とは区別する。

物体分類なら物体ごとに採点する。セグメンテーションでは、物体ごとのIoUを平均するか、全点をまとめるかで重みが変わる。集計方法を省くと、点数の多い対象がどれだけ結果を左右したか分からなくなる。

学習seedを変える反復では学習のばらつきを、対象を取り直す反復では対象によるばらつきを見る。ここでは、分割と対象を対応させた手法間比較を基本に考える。区間推定をするなら、点ではなくどの単位を再標本化するのか、その依存構造と仮定も説明する。固定seedは再実行を助けるが、一回の結果で十分という理由にはならない。[3]

## 次に実験を組むときの手元メモ

以下はこのノートでの提案。論文共通の規格ではない。取得元IDが分からなければ、まずそこが未解決になる。モデルを替えても分割の曖昧さは埋まらない。

| 比較前に決めること | 残しておくもの |
| --- | --- |
| 入力をどこまで加工するか | 点数、座標単位、属性、サンプリング、正規化のfit範囲 |
| 何を未知として測るか | 取得元IDとsplit、重複の扱い、対象数・クラス内訳 |
| どんな劣化を加えるか | 生成コード版、種類・強度、乱数、適用順序 |
| どの候補を採用するか | 検証指標、探索予算、停止条件、全seedと失敗試行 |
| 何を一票として採点するか | 物体／点／クラス平均の定義、適応範囲、欠損予測の扱い |

再実行用のmanifestには、dataset名・version、取得元IDとsplit一覧、そのhash、前処理設定と学習済み統計、分割・学習・劣化のseedsをまとめる。コードcommit、依存版・OS・機器、checkpointと選択理由、metricの定義も一組にする。

最後に、対象ID付きのraw predictions、ラベル対応、失敗ログ、適応の設定を保存する。集計値だけを残すより、どの対象で外したのかへ戻れるほうが、次の疑問を調べやすい。

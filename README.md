# knowledge

読んだ記事と論文のメモ。手法の名前だけでなく、何ができて、どこで話が変わるのかを残しておく。

たとえば、IRの命令が減ることとプログラムが速くなること。点の順番を変えても答えが変わらないことと、点が欠けても当たること。似た説明を並べていると見落としやすい違いを、[テーマ別のノート](topics/README.md)で考えている。

## どこから読むか

- **「速くなった」の中身を確かめたい** → [コード最適化の比較](topics/code-optimization-evaluation.md)。数字の単位、正しさ、候補を選ぶ予算を順に見る。
- **点群の実験を組む前に** → [点群を学ぶ4ステップ](topics/README.md#点群を学ぶ4ステップ)。PointNetから入り、最後にデータの分け方へ戻る。
- **証明器が通したものを、どこまで信じてよいか** → [証明の検証](topics/formal-proof-validation.md)
- **3Dで表示できた。その先で寸法を変えたい** → [CADの表現選び](topics/cad-representations.md)
- RAG、MLGO、証明探索、Text2CADの仕組みを図からたどるなら、[四つの研究ノート](topics/README.md#図解で読む四つの研究)へ。

月別の記事、年別の論文、当時の日誌はそのまま残してある。新しい横断ノートには、資料から分かったことと、そこから考えた比較の仕方を書く。試していない例は試したことにしない。出典の確認日も、公開日や動作確認の日とは分けている。
